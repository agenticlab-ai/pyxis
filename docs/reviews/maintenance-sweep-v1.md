### FND-2 — the exit-code contract leaves the partial-fault/zero-findings cell unmapped, and the fault-vs-findings ranking contradicts between the design's DINV-4 and the shape's matrix

- **Severity**: blocking (CAL-4 — escalation condition met: the gap is load-bearing for A-6/A-7, whose "exit honest" assertion is unfalsifiable for the unmapped cell)
- **Lens**: feasibility-completeness
- **Evidence**: design: "the exit code reflects the worst outcome present" (DINV-4) and "exit **0** clean · **1** findings-present · **2** fault (usage, misparse, unreadable state, malformed policy)" (§3.3 — the parenthetical enumerates pass-level faults only) — vs — shape: "exit 0: clean — every detector ran, zero findings, **zero faults**", "exit 1: findings — at least one finding emitted (faults may coexist; 1 wins over 0)", "exit 2: fault — usage/misparse, unreadable repo state, absent toolchain, malformed policy (incl. reasonless waiver), **or every detector faulted**". A pass where *some but not all* detectors fault and zero findings emit satisfies none of the three definitions: not 0 (a fault exists), not 1 (no finding), not 2 (neither a pass-level fault nor every-detector-faulted) — yet DINV-4 requires the exit to reflect the worst outcome present, and the PRD's UB-3 fit ("findings-present-or-fault exit code honest") demands a defined answer. Where findings and a detector fault coexist, the shape assigns 1 while DINV-4's "worst outcome present" reads as 2 if a fault outranks findings — the ranking is stated nowhere. The `outcome` enum ("clean|findings|fault") inherits the same ambiguity for the unmapped cell.
- **Acceptance condition**: the design's §3.3 (or DINV-4) states the outcome ranking and the partial-fault mapping explicitly — e.g. a detector fault with zero findings is a fault outcome (exit 2), findings-with-coexisting-fault stays 1 (or the reverse, with reason) — and the shape's exit fence realizes the same mapping; A-7 then names the zero-findings fault-injection variant so the cell is pinned by fixture.
- **Disposition**: applied — §3.3 pins the exit ranking (any finding → 1 with a coexisting fault named, never absorbed; zero findings + any fault → 2; else 0) and maps `outcome` by the same ranking; DINV-4 reworded to the pinned ranking; the shape's exit fence realizes it verbatim (the every-detector-faulted clause replaced by any-fault-with-zero-findings); A-7 pins both variants by fixture (zero-findings fault → exit 2 `outcome: fault`; findings-with-fault → exit 1, fault named).
