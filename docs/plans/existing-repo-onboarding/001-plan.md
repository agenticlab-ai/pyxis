### T1 — Expose converge's write primitives independent of Run

| Field | Value |
|---|---|
| **Blocked by** | — |
| **Size band** | 130–240 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/converge (converge.go Run loop, the per-class writers) |

**Goal:** The engine-verbatim and generated per-class writes converge performs inside Run become callable primitives adopt can invoke without running a full converge.

**Current behavior:** converge exposes a write-free classification callable (the scan/drift face) but the per-class writes live inline in the Run loop, entangled with archive acquisition and per-file manifest re-hash; there is no engine-verbatim-repair or generated-render primitive to call, and the drift face returns findings without the generated files' desired bytes.

**Desired behavior:** a caller can, from a classification and the verified release archive, drive the engine-verbatim and generated writes for a chosen path set through named primitives that return the action set — without invoking Run. Run's own behavior and its steady-state repair are byte-unchanged.

**Scope:**
- Extract the engine-verbatim repair and the generated render into callable primitives that accept the verified archive and the desired generated bytes and return the action set.
- Surface the generated-class desired bytes alongside the classification findings so a caller has what a write needs.

**Out of scope:**
- Any change to Run's steady-state semantics or its result (a pure extraction; NR-2).
- The adopt module itself (T3, T8).

**Acceptance criteria:**
- [ ] The engine-verbatim and generated writes are invocable for a given path set from a classification + verified archive, returning the action set, without calling Run.
- [ ] The existing converge steady-state repair suite passes byte-unchanged.

**Key interfaces:**
- The converge classification result type (extended to carry generated desired bytes); the new engine-verbatim and generated write-primitive function contracts.

### T2 — The adoption-plan artifact: schema and render

| Field | Value |
|---|---|
| **Blocked by** | — |
| **Size band** | 150–260 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt (the adoption-plan schema type + parser + renderer) |

**Goal:** A closed schema-versioned adoption-plan record that carries, per acted-on path, its class and — after apply — its undo baseline, plus a human-readable render of it for review.

**Current behavior:** no adoption-plan type exists.

**Desired behavior:** an adoption-plan record parses and serialises under a closed schema (unknown keys refused): per-path entries with a class and detail; the displaced prior hook path; the detected stacks and their required gate-command actions; the added-path set each carrying a content hash captured at apply; the epoch; and a draft-or-applied lifecycle state. A renderer turns it into a reviewable human face.

**Scope:**
- The closed adoption-plan schema type with its class enum, the added-path baseline hash per entry, the hooks, stack, and epoch blocks, and the draft-or-applied state.
- A deterministic human-readable render of a plan.

**Out of scope:**
- Producing a plan (T3) or consuming one (T8, T10) — this task is the artifact and its render only.

**Acceptance criteria:**
- [ ] A well-formed adoption-plan round-trips through parse and serialise; an unknown key is refused by name.
- [ ] The render of a fixture plan is a stable, reviewable human face (golden).
- [ ] Exactly one adoption-plan record represents a given adoption — the schema has no second record of the same fact.

**Key interfaces:**
- The adoption-plan schema type; its class enum; the added-path entry shape carrying the baseline hash.

### T3 — adopt inspect and plan: dispatch, classify, and draft the plan

| Field | Value |
|---|---|
| **Blocked by** | T2 |
| **Size band** | 170–280 |
| **Mechanical** | no |
| **Size accepted** | atomic — the inspect read is one behavior (dispatch, classify, assemble); splitting the dispatch from the classify would ship neither demoably |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt (the inspect and plan operations) · cmd/adopt (the verb entry) · internal/converge (consume the classification face) |

**Goal:** Running the adopt verb in plan mode on a non-empty repository writes a correct draft adoption-plan and mutates no tracked file.

**Current behavior:** no adopt verb exists.

**Desired behavior:** adopt first dispatches by tree state — a non-git target is refused by name before any inspection; an empty tree routes to the empty-repo install path and writes no plan; a repository carrying a prior adoption config that is absent-but-required, partial, or malformed is refused by name. A non-empty git repository is classified against the release manifest (reusing converge's classification), the never-touch set is taken as the manifest's complement, and the classified entries are assembled into a draft adoption-plan. Plan mode writes only the plan.

**Scope:**
- Tree-state dispatch: non-git refusal, empty-tree routing to init, and prior-config refusal, each by name.
- Classify the non-empty tree by reusing converge's classification; take never-touch as the manifest complement.
- Assemble the classified entries into a draft adoption-plan; write nothing else.

**Out of scope:**
- Detecting the stack (T4) and resolving collisions (T5, T6, T7) — those enrich the plan in their own tasks.
- Applying anything (T8).

**Acceptance criteria:**
- [ ] adopt in plan mode on a non-empty fixture writes only the plan artifact; every other tracked path is byte-identical before and after.
- [ ] An empty tree routes to init and writes no plan; a non-git target refuses by name and writes nothing; a malformed prior config is refused by name.
- [ ] The draft plan classifies each acted-on path and lists the never-touch set as the manifest complement.

**Key interfaces:**
- The adopt inspect and plan operation contracts; the converge classification consumer.

### T4 — Stack detection into the plan

| Field | Value |
|---|---|
| **Blocked by** | T2 |
| **Size band** | 110–190 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt (the detection step) · internal/verify/ecosystem (reuse the marker registry) |

**Goal:** The plan names every stack the repository's markers identify and the gate-command action the adopter must supply, inventing no command.

**Current behavior:** the ecosystem marker registry classifies stacks for other purposes; adoption does not consult it.

**Desired behavior:** detection reads the existing marker registry and records, in the plan's stack block, every detected stack and the required per-command gate action for each; a repository no marker matches yields a single unknown-stack line asking the adopter to set the gate commands — never an error, never a fabricated command.

**Scope:**
- Read the existing marker registry; name every detected stack and its required gate-command action into the plan.
- Degrade an unrecognised repository to a single unknown-stack line, no error.

**Out of scope:**
- Wiring or running any gate command (detect-and-surface only); shipping language profiles.

**Acceptance criteria:**
- [ ] A Go and a non-Go fixture each yield a plan naming the detected stack and the required gate-command action; no command is fabricated.
- [ ] An unknown-stack fixture yields a plan carrying the unknown-stack line, not a failure.

**Key interfaces:**
- The marker-registry consumer; the plan's stack block.

### T5 — Hook-path collision: chain forward, restore on undo

| Field | Value |
|---|---|
| **Blocked by** | T2, T3 |
| **Size band** | 150–250 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt (the hook resolution) · the engine hook shim (forward delegation) · internal/converge/doctor (displaced-path check) |

**Goal:** Adoption chains the engine's pre-push checks in front of the adopter's existing hook path without touching the adopter's hook content, and reversal restores the prior path exactly.

**Current behavior:** the engine's hook is engine-verbatim and delegating (phase-1), but there is no adopt-time chaining onto an existing hook path.

**Desired behavior:** the plan records a hook-chain entry when the repository already sets a hook path. Apply sets the hook path to the engine's own directory and the engine's hook, after its checks, invokes the adopter's previously-configured hook. Apply records the displaced prior path into the plan before it overwrites the hook-path setting, and is idempotent — if the hook path already resolves to the engine's directory, the capture is skipped so a re-apply never records the engine's own directory as the prior path. Undo restores the recorded prior path. Doctor names a hook path that has been displaced since adoption.

**Scope:**
- Plan a hook-chain entry when a prior hook path exists; apply sets the engine hook path, records the prior first, delegates forward, and is idempotent on re-apply.
- Undo restores the recorded prior hook path; doctor reports a displaced hook path.

**Out of scope:**
- The full apply orchestration and undo orchestration skeletons (T8, T10) — this task is the hook resolution those orchestrators call.

**Acceptance criteria:**
- [ ] On a hook-manager fixture, the pre-existing hook is byte-identical after apply and still runs; the engine's checks run ahead of it.
- [ ] Undo restores the prior hook path; a re-apply does not overwrite the recorded prior path with the engine's own directory.
- [ ] Doctor names a hook path displaced since adoption.

**Key interfaces:**
- The hook-chain resolution contract; the plan's prior-hook-path field; the doctor adoption-state check.

### T8 — apply: materialise the approved plan, record the epoch

| Field | Value |
|---|---|
| **Blocked by** | T1, T5, T6, T7 |
| **Size band** | 160–280 |
| **Mechanical** | no |
| **Size accepted** | atomic — apply is one behavior (orchestrate the resolutions, record the epoch, stamp the receipt); the pieces do not ship demoably apart |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt (the apply orchestration) · internal/converge (the write primitives from T1) |

**Goal:** Applying an approved plan materialises exactly that plan, records the install epoch without creating a commit, and stamps the plan applied so undo can reverse it.

**Current behavior:** no apply exists; the epoch config field is present but written only by init, and consumed nowhere.

**Desired behavior:** apply refuses a plan that is absent or stale relative to the tree. Otherwise it drives the engine-verbatim and generated writes through the converge primitives (consuming the desired generated bytes and the verified archive), applies the collision resolutions, records the repository's current commit as the epoch while creating no commit of its own, and stamps the plan applied — populating each added path with the content hash undo's detection compares against. A re-apply lands only content that has drifted from the plan and makes no other change. Apply changes no path the plan does not name.

**Scope:**
- Orchestrate the per-class writes (via T1) and the collision resolutions (T5, T6, T7); refuse an absent or stale plan.
- Record the epoch as the current commit, create no commit; stamp the plan applied with the added-path baselines.
- Idempotent re-apply lands only drift.

**Out of scope:**
- Gate consumption of the epoch (T9); undo (T10).

**Acceptance criteria:**
- [ ] Applying the fixture plan produces the intended tree; no path absent from the plan changes; a second apply lands zero further changes.
- [ ] Apply records the epoch as the current commit and creates no commit of its own.
- [ ] Apply with no approved plan, or a plan stale relative to the tree, refuses by name and changes nothing.
- [ ] The applied plan carries a content baseline for every added path.

**Key interfaces:**
- The apply orchestration contract; the converge write primitives; the epoch config field.

### T9 — Install-epoch gate scoping

| Field | Value |
|---|---|
| **Blocked by** | T8 |
| **Size band** | 130–230 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/docgate/gate (the scan-set construction) · internal/converge/doctor (epoch reporting) |

**Goal:** The tree-local documentation gates judge only content changed since the epoch, so an adopted repository's pre-existing corpus is grandfathered and gate cost scales with the changed set, not the corpus.

**Current behavior:** the tree-local gates judge the whole current tree with no history notion; the epoch is recorded (T8) but consumed nowhere.

**Desired behavior:** when an epoch is set, tree-local gates compute the set changed since the epoch once per run and check only its intersection with the scan-set; history-scoped checks are unaffected. An unreachable epoch commit fails closed — gate everything, naming the cause. The per-check grandfather exception lists remain available alongside the epoch. Doctor reports the epoch. A post-epoch change to a file is fully gated.

**Scope:**
- Filter the tree-local gate scan-set by the set changed since the epoch, computed once per run; fail closed on an unreachable epoch.
- Doctor reports the adoption epoch; the grandfather exception lists coexist.

**Out of scope:**
- Recording the epoch (T8); history-scoped checks (unchanged).

**Acceptance criteria:**
- [ ] A non-conforming-corpus fixture is gate-green immediately after adoption; a post-epoch change to a file is fully gated.
- [ ] For a fixed change-set against a growing corpus, the gate makes one changed-set computation and visits only the changed-set-and-scan-set intersection, both invariant to corpus size.
- [ ] An unreachable epoch commit gates everything, naming the cause; the grandfather exception lists still apply.

**Key interfaces:**
- The gate scan-set construction; the epoch config field; the doctor epoch check.

### T10 — undo: remove the installation, preserve post-adoption work

| Field | Value |
|---|---|
| **Blocked by** | T8 |
| **Size band** | 150–250 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt (the undo orchestration) |

**Goal:** Undo removes the installation and preserves the operator's post-adoption work, failing closed on any added artifact the operator has modified.

**Current behavior:** no undo exists.

**Desired behavior:** undo unchains the hook (restoring the prior path), deletes the added paths, clears the epoch, and names the manual-instruction entries for the human to reverse — leaving every post-adoption commit and edit in place. Its modified-since-adoption test is decided per ownership class against the baseline captured at apply: an engine-verbatim path against its manifest hash, a generated path by regenerate-and-compare, an added path against its stored baseline. A path whose current hash differs from its baseline is preserved and named, never deleted; undo completes the rest of the removal.

**Scope:**
- Reverse the applied plan: unchain and restore the prior hook path, delete the added paths, clear the epoch, name the manual entries for reversal.
- Per-class modified-since-adoption detection; preserve-and-name a modified added artifact.

**Out of scope:**
- Apply (T8); the round-trip proof harness (T11).

**Acceptance criteria:**
- [ ] After adopt then undo on a fixture, the tree is byte-identical to its pre-adoption state and a post-adoption commit survives.
- [ ] After adopt, editing a chained-hook artifact, then undo, the modified artifact is preserved and named and the rest of the installation is removed.
- [ ] Undo names the manual-instruction entries for the human to reverse.

**Key interfaces:**
- The undo orchestration contract; the per-class detection against the plan baselines.

### T11 — The round-trip acceptance harness

| Field | Value |
|---|---|
| **Blocked by** | T9, T10 |
| **Size band** | 150–260 |
| **Mechanical** | no |
| **Size accepted** | — |
| **Overlap accepted** | — |
| **Routing** | — |
| **Pattern** | — |
| **Touches** | internal/adopt end-to-end test harness · the fixture repository builder |

**Goal:** A hermetic end-to-end proof that adoption of a repository carrying every collision reaches gate-green, never touches what the repo owns, and reverses byte-for-byte — with the empty-repo and steady-state paths unregressed.

**Current behavior:** no adoption end-to-end harness exists; the installer end-to-end fixture and removal-test patterns are the reuse base.

**Desired behavior:** a fixture repository carrying every collision at once — an existing root convention file, a hook-manager hook path, a name-colliding workflow, a non-conforming corpus, and a non-Go stack — is git-initialised at a pre-adoption commit and adopted end to end. After apply, a repository-diff restricted to the paths outside the plan's managed set is empty (the never-touch set is byte-identical). After undo, the working tree and head equal the pre-adoption commit. The manual-instruction lines are the only human work needed to reach green. The empty-repo install and converge steady-state suites pass unchanged.

**Scope:**
- Build the all-collisions fixture repository; run adopt, apply, undo end to end.
- Assert never-touch byte-identity after apply and whole-tree equality to the pre-adoption commit after undo, git-natively.
- Assert the empty-repo install and converge steady-state suites pass unchanged.

**Out of scope:**
- The mechanisms under test (T1–T10) — this task is the harness and its assertions.

**Acceptance criteria:**
- [ ] The all-collisions fixture adopts to gate-green; the never-touch set is byte-identical before and after apply; the whole tree is byte-identical to its pre-adoption commit after undo.
- [ ] The emitted manual instructions are the only human work needed to reach green.
- [ ] The empty-repo install path and converge steady-state repair suites pass unchanged.

**Key interfaces:**
- The fixture-repository builder; the git-native never-touch and round-trip assertions.
