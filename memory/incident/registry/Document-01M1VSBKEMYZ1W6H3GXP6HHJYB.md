# Incidents registry

The middle tier of this repo's memory: between the distilled principles in
[`../architecture-principles.md`](../architecture-principles.md) (top) and
closed issues (bottom) sits the lesson that informs a specific design decision
— *"we tried X here and it broke this way"*. Too specific to be a principle,
too expensive to relearn. This file is its shared, greppable home.

The data flow is one-directional: **observability records reality → the design
stage consults it before deciding.** Design-stage work greps this file by
subsystem tag to load the paid-for lessons before drafting.

## Format / legend

Each incident is one bounded entry (~6 body lines). The first line is the
load-bearing index:

```
**I<n> (YYYY-MM-DD) [tag, tag, …]**
```

- **`I<n>`** — a stable citable ID (`I1…In`), **never renumbered**.
- **`(YYYY-MM-DD)`** — the date the lesson was paid for.
- **`[tag, tag, …]`** — bracketed subsystem tags are the lookup key; consumers
  grep their tags and read only matching entries, never the whole file.

The body is a fixed four-field shape:

- **Decision:** what was decided / built.
- **Broke:** how it broke (the observed failure).
- **Lesson:** the distilled takeaway — what to do instead.
- **Links:** provenance — the issue(s)/change(s) involved and, once graduated,
  `Graduated: AP-<n>`.

**Graduation direction is one-way: registry → principle.** When a lesson is
distilled into `architecture-principles.md`, the entry's `Links:` line gains
the `Graduated:` pointer; the principles file never links back down.

**I5 (2026-07-21) [code-gate, implement-now, ci-mirror, hermeticity]**

- **Decision:** The executor local gate (executor.gate) was hand-listed as `go build/vet/test ./...` — a deliberate subset of required CI (gofmt, `go test -race`, docgate); the argv-only config could not express the rest, so those were declared CI-authoritative. Two independent lists, presumed to agree.
- **Broke:** The first implement-now sweep: task T10 (#600) drove green through the local gate but stranded required docs-gate CI red at `go test -race ./...` → internal/verify/checks/TestRung0Latency (rung-0 20.2s over the NFR-1 10s budget). Measurements record; they never gate.

**I7 (2026-08-03) [implement-now, rate-limit, fail-closed, cold-start]**

- **Decision:** The self-drive-wake write budget contracted one recovery rule for three different states: prd:self-drive-wake §5.4's throttle-ledger row and design:state-reader-v2 §3.8/DINV-6 both say a corrupt, unreadable, OR missing ledger starts conservative (both windows assumed fully spent) — while the same §5.4 row simultaneously declares the ledger "ephemeral; safe to delete (rebuilds conservatively)". The implementation followed the contract faithfully and stored the ledger inside the driver's own repository checkout (cmd/implement-now/run.go:149).
- **Broke:** Every ephemeral driver checkout starts without a ledger, and budget.read() collapses every os.ReadFile error — ErrNotExist included — into spent(now), so a fresh driver recorded 80/80 minute and 500/500 hour writes as spent at first use and blocked its first content write for 59m59s. Hit on implement-now task T3: branch pushed, draft-PR creation parked ~1h with the claim held and no worker running. Nothing surfaced the deadline — the contracted EVT-4 throttle_deferred event is never emitted (EventBudgetDeferred is a dead constant), and the one log line, 'github content write deferred queue_depth=1 deferred=0s', reported elapsed instead of projected wait and then went silent for the hour. The cold-start path also persisted the fabricated 580-entry ledger before sleeping, extending the block to every process sharing that checkout.
- **Lesson:** 'Fail closed on bad state' is two rules wearing one name: state that EXISTS BUT CANNOT BE READ may hide spend the reader cannot see and must fail closed; state that is ABSENT had no prior holder, can hide nothing, and must start empty. Conflating them converts a safety rule into a self-inflicted outage, and a contract that calls state 'safe to delete' while charging for its absence is internally contradictory — that contradiction is reviewable on the page, before any code exists. Two corollaries: shared-quota state keyed to an ephemeral workspace is not machine-shared however its doc comment reads, so key it to the entity the platform actually meters (and never partition finer than the platform documents its limit — GitHub publishes the content-write caps but not their scope); and a backpressure wait that logs only elapsed time is unobservable — the projected wait and reset deadline are the operator's only evidence that a stall is throttling rather than a hang.
- **Links:** PR #961 (prd:self-drive-wake amendment 001, the contract fix) · prd:self-drive-wake §5.4 · design:state-reader-v2 §3.8/DINV-6 (and its DINV-7 'safe to delete' claim) · internal/executor/budget/budget.go (read/spent/nextWait) · cmd/implement-now/run.go:149 · prd:self-drive-wake/EVT-4 · internal/watch/events.go:32

- **Decision:** The watch loop's sweep trigger was implemented as an edge on the WHOLE derived await set plus an unconditional cadence force, while its governing design specifies the ready-task trigger (wake-watch-v2 §3.1 step 1 — ready-but-unclaimed are the awaits that "trigger a sweep"; #DINV-9). **I9 (2026-08-07) [plangate, plan-new, traceability, immutability]**

- **Decision:** Plans freeze at merge exactly as designs do, and every plan task cites the PRD requirement IDs it delivers in its Traces and Coverage rows; the PRD ledger meanwhile evolves by typed amendments that supersede rows and retire their IDs. The two rules were never reconciled: nothing in the amendment path looks at plans, and nothing in the plan class tolerates a trace whose target has been superseded.

**I10 (2026-08-07) [implement-now, drive-to-green, fail-closed, github, read-after-write]**

- **Decision:** The drive-to-green repair loop guards every write behind a fresh proposal observation: it remembers the head it expects and stops fail-closed when the proposal's head advances while a repair is in flight, so a repair never fights a human who pushed or merged mid-flight (proposalMovement's open-head-advance branch). After its own re-push the loop re-reads the proposal with an EMPTY expected head, letting whatever that first observation returns seed the head it will expect on the next attempt.
- **Broke:** Observed live twice in one sweep — on both tasks it dispatched, plan e2e-verification/002 T1 and T2. Each attempt-2 fixer passed the local gate and pushed its fix, advancing PR #1075 from dc41aa8 to 8d80ad1 and PR #1074 from e4f1f3f to 7360494. In both the post-push settle read the proposal back before the code host reflected that push and stored the STALE pre-push head as the expected head; the next attempt's revalidate then observed the real pushed commit, classified the loop's own work as foreign movement, and failed the task closed with an escalation demanding human attention. The sweep reported 0 succeeded and 2 failed while PR #1075's required check had in fact gone green.
- **Lesson:** A guard that detects 'someone else moved this' must be able to recognise the mover's own writes. The loop knows exactly which commit it pushed, so the head to expect after a re-push is a value it already holds, not one to rediscover by reading back a code host that is only eventually consistent — seeding it from a post-write read makes the guard's correctness depend on replication timing, and the stale read is the ordinary case, not the rare one: it took every task in the sweep. Where a read-back is unavoidable, treat 'the head equals the commit I just pushed' as self-movement and continue, reserving the escalation for a head neither expected nor authored by this loop. A false fail-closed is not free — it spends a human's attention, marks finished work failed, and abandons a proposal that had already gone green.

**I11 (2026-08-10) [implement-now, code-gate, ci-mirror, drive-to-green]**

- **Decision:** The executor's local gate was rebuilt after I5 to mirror required CI exactly — one per-repo check list run by one verb — and prd:implement-now/UB-5 names its observable as a red local gate BEFORE push. The implementation wired that predicate at two moments only: before each re-push inside the drive-to-green repair loop, and before publishing a bound-truncated run's committed work. The ordinary clean-agent-exit path pushes the branch and opens the proposal with no gate call at all. Separately the workspace adapter repoints the clone's core.hooksPath at its own guard directory so a worker cannot commit in the parent checkout; that directory carries no pre-push hook, so the repo's own docgate + code-gate pre-push shim is displaced while the executor runs.
- **Broke:** Plan e2e-verification/002, tasks T5 and T9, in one sweep. Both workers finished cleanly, pushed, and opened proposals #1083 and #1084 carrying unformatted Go — gofmt alone; vet, build and the race suite were green on both. Nothing between the agent's last commit and the open proposal inspected the code: the worker path never called the gate, and the pre-push hook that would have caught it was absent from the guard directory the executor had pointed the clone at.
- **Lesson:** A gate only protects what it is invoked before. Wiring the CI mirror into the repair loop and the truncation path left the route most work takes publishing unverified, so CI became the first thing to read an ordinary change and the contract's stated observable went unmet on the majority path — and every occurrence spends a CI round trip plus a model call out of a bounded self-heal budget meant for genuine failures. Check a predicate's call sites against the moments its requirement names, not against the places it was needed while building. Second: an adapter that repoints core.hooksPath to guard one thing disarms every other hook the repo relies on and leaves it disarmed after the run — a guard that takes over a hook chain must carry the hooks it displaces.

**I12 (2026-08-10) [implement-now, self-drive, watch, fail-closed]**

- **Decision:** Three rules decided separately and never composed. A worker that judges its task already satisfied makes no commit and exits; the executor verifies by artifact, so a worktree with no commits beyond base is hollow — a terminal failure carrying a fail-closed escalation (DINV-3). A sweep exits non-zero whenever any task failed, deliberately, so a failed task can never read as a clean idle pass (AP-16, cmd/implement-now/run.go:273). And drive mode's watch loop treats ANY error from a sweep as fatal and returns (internal/watch/live.go:77) — a rule written for a sweep that could not run, inherited by a sweep that ran fine and reported a failure.
- **Broke:** Plan e2e-verification/002 T6. The worker attributed the task's deliverable to the already-merged T1, wrote nothing, and exited clean — while its own transcript recorded 'I haven't found evidence that the e2e-design skill actually authors blocking open items' two paragraphs before concluding the implementation was complete. It was not: the authoring guide writes the document to its final path and then checks it, the reverse of the check-before-emit ordering the task names, and neither the re-route path that lifts the hold nor the unsettleable-harness fixture existed anywhere in the tree. The hollow carried no error, so the escalation logged reason="". The sweep then exited 1, the watcher propagated it and exited after five hours of unattended driving, and T12 — whose only outstanding blocker was T6 — never ran.
- **Lesson:** A per-task failure must not end the drive. The exit convention that reddens a single bounded sweep becomes, under a watcher that treats sweep error as fatal, a rule that one task's misjudgment strands every remaining independent task; the frontier still held work that had nothing to do with the failure. A driver must distinguish 'this sweep ran and found a failed task' from 'this sweep could not run' — only the second is fatal to the loop. Second: 'nothing to do' is a claim that needs evidence against the task's own acceptance criteria, never against a sibling task's commit, and a worker that records evidence contradicting its own conclusion should fail its check rather than round up to complete. Third, smaller but compounding: hollow is the one failure class where the executor knows exactly what happened, and it is the only one that escalates with an empty reason, because a no-op exit produces no error text to carry.
