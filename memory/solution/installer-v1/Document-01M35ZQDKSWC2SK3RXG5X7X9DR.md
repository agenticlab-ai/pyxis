# Installer v1 — solution shape

| Field | Value |
|---|---|
| **Design** | installer-v1 |
| **Status** | authoritative |

**The release artifact set** — one tag `vX.Y.Z` publishes (names final at implementation; the manifest, not the naming, is the contract — DINV-2):

```
pyxis-vX.Y.Z-<platform>            # the orchestrator binary, per platform tuple
<tool>-vX.Y.Z-<platform>           # every engine binary the cmd/ scan derives, per platform
payload-vX.Y.Z.tar.gz              # the .pyxis/ system tree (skills, templates, authoring,
                                   #   scripts, hooks, ui, independently consumed assets)
release-manifest-vX.Y.Z.json       # §below — the trust root's object
SHA256SUMS                         # every artifact above
```

**The release manifest** (`release-manifest/v1`, closed parse — DINV-2, DINV-6; generated by the release build from the class policy, never authored):

```jsonc
{
  "schema_version": "release-manifest/v1",
  "system_version": "vX.Y.Z",
  "source_commit": "<sha>",                    // provenance: tag == commit == artifacts
  "binaries": {
    "docgate":  { "darwin-arm64": "<sha256>", "linux-amd64": "<sha256>" /* … per platform */ },
    "pyxis":    { /* listed for converge/doctor parity; the BOOTSTRAP's anchor is the pin documented in the install instructions — independent of this manifest (design §3.4) */ }
    /* every cmd/-scanned tool — the set is derived, never enumerated by hand (AP-27) */
  },
  "payload": {
    "archive_sha256": "<sha256>",
    "files": [
      { "path": ".pyxis/templates/prd-template.md", "sha256": "<hex>", "class": "engine-verbatim" },
      { "path": ".pyxis/config.yaml",               "sha256": null,    "class": "repo-owned" },
      { "path": "docs/tech-design/index.json",      "sha256": null,    "class": "generated" }
      /* every installed file, exactly one class each (design DINV-6) */
    ]
  }
}
```

**The class policy** (`class-policy/v1` — the authored input, AP-24; committed in the source repo; glob → class, first match wins, unmatched fails the build — realizes design DINV-6 and A-11):

```yaml
schema_version: class-policy/v1
classes:
  - { glob: ".pyxis/config.yaml",        class: repo-owned }     # the knobs + paths + pins + epoch
  - { glob: ".pyxis/stamp/**",           class: repo-owned }
  - { glob: ".pyxis/vendor/**",          class: engine-verbatim }
  - { glob: ".pyxis/**",                 class: engine-verbatim } # templates, skills, scripts, hooks, ui
  - { glob: ".github/workflows/docs-gate.yml", class: engine-verbatim }  # the INSTALLED-repo variant (design §3.10):
                                                                          #   exec-grammar gate steps, zero source-toolchain steps
  - { glob: "docs/tech-design/index.*",  class: generated }
# seeded skeletons (vision/principles/domain/system docs) AND the operand manual
# (AGENTS.md) are instantiated by init, not shipped-in-place: repo-owned from
# birth and never listed here (design §3.5 step 4).
```

**The operand config** (`.pyxis/config.yaml`, schema v2 — closed parse; the dual-read migration window covers the prior per-tool pin sections, design §3.10 — realizes design DINV-2 and A-4; the paths block realizes FR-18's captured-refuse posture):

```yaml
schema_version: pyxis-config/v2
system:
  version: "vX.Y.Z"                  # the one release pin (design DINV-2)
  manifest_sha256: "<hex>"           # the trust root: everything else verifies through it
  artifact_source: ""                # optional FR-22 override (mirror/fork base URL);
                                     #   loudly reported by preview + doctor
  mode: release                      # release | source — source legal only where source lives
knobs:                               # the five, captured at init (prd FR-3)
  tracker: github                    # github | carina
  ci_mode: both                      # local | actions | both
  wiring: { repo: use, protection: required-checks }   # use|create · none|required-checks|checks+review
  cli_surfaces: [claude, codex]      # auto-detect result or explicit set
  argus: false                       # opt-in, off by default (prd FR-16)
branch: main                         # captured; only main honored in v1 (prd WR-9)
paths:                               # every consumed path, defaults captured (prd FR-18):
  prds: docs/prds                    #   a non-default value refuses by name until WR-10
  tech_designs: docs/tech-design
  solution_shapes: docs/solution-shapes
  # closed by construction: this schema IS the authoritative list — a conformance
  # check asserts no engine configurable-path read lacks a schema key (design §3.7)
epoch:                               # written once at init (design §3.5 step 8); doctor reports it
  system_version: "vX.Y.Z"
  commit: "<sha>"                    # the initial commit init created (adoption commit at WR-1)
  manifest_sha256: "<hex>"
```

**The pyxis verb surface** (all flags long-form; every verb refuses flag-like positionals and unknown flags pre-action — design DINV-5, prd UB-9):

```
pyxis init      [--answers <file>] [--tracker …] [--ci-mode …] [--wiring …]
                [--cli-surfaces …] [--argus] [--preview] [--yes]
pyxis converge  [--repair] [--preview]          # one converge; --repair is its name on damage
pyxis doctor                                    # read-only: drift by class, env, epoch, advisories
pyxis exec <tool> -- <argv…>                    # the grammar: nothing before -- reaches the tool,
                                                #   nothing after is interpreted
pyxis version
```

**The acquisition sequence** (design §3.4; per-exec, DINV-1):

```
config.system.manifest_sha256 ──verify──▶ release-manifest.json
        (cache: .pyxis/bin/release-manifest-<ver>.json — gitignored; fetched then
         verified against the config pin before first use; reaped off-version by converge)
        └─ tool + platform ──▶ expected sha256
.pyxis/bin/<tool>-<ver>-<plat>  hit? ── re-hash == expected? ──▶ execve
        │                                   └─ mismatch ─▶ refetch (tmp + atomic rename) or refuse
        └─ miss ─▶ fetch from source/override ─▶ verify ─▶ cache ─▶ execve
source mode: ──▶ go run ./cmd/<tool> (source repo only)
```

**The wiring operation table** (`internal/wire`; one row per declared operation — preview renders it, gh executes it, EVT-4 records it; design §3.6):

| op | gh surface | knob condition |
|---|---|---|
| ensure-labels | `gh label create/list` | tracker=github |
| push-workflow | commit in the converge set + push | ci_mode ∈ {actions, both} |
| set-protection | `gh api repos/…/branches/main/protection` | wiring.protection ≠ none |
| create-repo | `gh repo create` | wiring.repo = create |
| welcome-item | `gh issue create` (template-bodied) | tracker=github |

**New shipped instantiables** (payload templates; design §3.5 step 4): `product-vision-skeleton`, `architecture-principles-skeleton`, `domain-model-skeleton`, `system-design-skeleton`, `operand-agents-manual` (knob-substituted, then repo-owned), `welcome-item` (authorship pointers + first-feature path).

**Go surface** (thin main + packages; names final at implementation): `cmd/pyxis` over `internal/relmanifest` (closed schemas: manifest, class policy), `internal/converge` (ownership-class engine; doctor = read mode), `internal/resolve` (acquisition; the one checksum floor), `internal/installer` (knobs, seeding, epoch), `internal/wire` (operation table + gh transport). The release workflow (`system-release.yml`) supersedes the per-tool release workflow; publish is upload-or-verify.
