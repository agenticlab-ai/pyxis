## The ledger machinery

- **Ledger** — the immutable, dense-numbered sequence of merged PRD documents for one feature (`000-base.md`, `NNN-<slug>.md`, `NNN-rebase.md`). *(amendment model, Terms)*
- **Amendment** — a typed ledger entry that changes the effective contract: a thin envelope plus `### op:` blocks. *(amendment template)*
- **Envelope** — an amendment's closed header (Amends / Status / Owner / Date / Learned-from / Blast radius / Template version); this schema's authority is the amendment template, version-pinned. *(amendment template, appendix)*
- **Op (typed operation)** — one of the closed verbs (`add` · `supersede` · `retire` · `answer` · `rescope`), always carrying a complete resolved payload — nothing is left for the fold to interpret. *(amendment model §3)*
- **Fold** — the deterministic replay of the ledger that produces the projection; fails closed on any dangling or ambiguous op. *(amendment model §4)*
- **Projection / effective view** — the generated current state of a PRD: `effective.md` (human face) + `effective.source.json` (machine face). Derived, never authored; byte-verified in CI. *(amendment model §2, §4)*
- **Source map** — `effective.source.json`: per-unit status (`live` · `superseded-by` · `retired`), lineage, and locations; what the Contract Compiler, traceability, and invalidation consume. *(amendment model §4)*
- **Content fingerprint** — sha256 over the normalized replayed-ledger bytes; proves which contract state an artifact derives from. The `docgate` version is recorded alongside, never hashed in — tool releases never invalidate provenance. *(amendment model §4)*
- **Rebase checkpoint** — a human-approved **semantic no-op** snapshot of the projection, re-approved as the new replay base; `verify-rebase` proves it launders nothing. *(amendment model §6)*
- **Blast radius** — an amendment's declared impact tier (`additive` · `corrective` · `contract-changing`), written `tier; touches; reason`; `docgate` computes the minimum from the ops — declared may exceed computed, never understate. *(amendment model §7)*
- **Learned-from / evidence classes** — the typed, mandatory evidence field: `incident` · `review-thread` · `telemetry-query` · `build-result` · `user-research` · `support-ticket` · `operator-decision` · `dependency-change` · `policy-change`, each with a structured reference. *(amendment template)*
- **Downstream invalidation** — the freshness contract: every derived artifact records the ledger position + fingerprint + cited IDs it was built from; states are Unaffected / Stale / Blocked / Needs-recompile. *(amendment model §12)*
- **docgate** — the deterministic Go tool behind the `docs-gate` CI context and the desk hooks: the `fold` plus a gate/writer verb set that grows by amendment — enumerate it via `docgate` usage or `docs/techspec.md`, never from memory (frozen counts rot). *(amendment model §5; docgate ledger)*

## The PRD contract

- **Routing surface** — the `In one line` + `Relevant-when` header rows: what an agent reads to decide load-or-skip without opening the document. *(prd-template how-to)*
- **Tier (T1/T2/T3)** — the PRD's rigor level, scaled to risk and blast radius, deciding which sections are required; §5.8 and §8 are never skipped. *(prd-template how-to)*
- **Appetite** — the total spend a problem is worth: human attention + machine work + rollout/support burden. A budget, not an estimate; never expressed in time. *(prd-template header)*
- **Fit criterion** — the measurement attached to every requirement that decides pass/fail; a requirement without one is not yet understood. *(prd-template Appendix A)*
- **EARS** — the constrained requirement sentence patterns (ubiquitous / event / state / optional / unwanted-behavior / complex). *(prd-template Appendix A)*
- **Verification methods** — Test · Demo · Inspection · Analysis · Eval · Human judgment (the last only with a named owner and rubric). *(prd-template Appendix A)*
- **DoD (Definition of Done)** — §5.8: the single executable completion checklist, aggregating by reference; what the factory verifies against. *(prd-template §5.8)*
- **Contract readiness** — §8: the executability gate ("can the factory build and verify this without guessing?"), the authoring-side mirror of pipeline stage 6. *(prd-template §8)*
- **Gates (problem / solution / launch)** — the sign-off points in a PRD's draft phase; zero solution-blocking TBDs may pass the solution gate. *(prd-template §2/§4/§6)*
- **Read to rule (§0)** — the PRD's human-only routing section: what the gate-signing reviewer must judge — the ranked judgment calls, the sanity-check numbers, the author's open questions, and the informed-skip map; informative never normative (on conflict the body governs); machines ignore it entirely. Avoid: *brief* (the DecisionBrief is prd-review's escalation payload), *summary* (§1's job), *review report* (the unmanned reviewer's artifact). *(prd:read-to-rule)*
- **Non-goal (NG-n) / Waiting room (WR-n)** — the anchored boundary: deliberate refusals with reasons, and deferrals with revisit triggers; `rescope` operates on these anchors. *(prd-template §3.4)*
- **Checkpoint** — an observable exposure condition (rollout stage reached, N users/tasks through a flow) that metric targets bind to — never a calendar date. *(prd-template §3.2)*
- **ID namespaces** — the global per-PRD anchor set (`G J F M FR NR UB ABUSE NFR EVT DOD EVAL NG WR Q R`); no ID is ever reused. *(prd-template Appendix A)*

## The design class

- **Serves** — the typed requirement→design join on every design header: `prd:<feature>/FR-3` · `corpus:VNEXT-8` · `design:<slug>[#anchor]` · `doc:<path#anchor>`; `—` only for infrastructure/governance work. The stage-6 compiler's join key. *(tech-design-conventions §3.1)*
- **Supersedes (designs)** — successor-declared, whole-document replacement: the new design names the old; the old is never edited; liveness is computed by the index. Contradiction *requires* supersession — two live designs never disagree. *(tech-design-conventions §2)*
- **DINV-n** — design-local invariant anchors (binding, property-test material; `INV-n` is the domain registry and `I1…` the incident registry, both taken); cited externally as `<slug>#DINV-1`; graduate to the domain INV registry when load-bearing beyond one design. *(tech-design-template §3.3)*
- **Binding elements** — `**Decision:**` callouts, `DINV-n` invariants, and `A-n` acceptance rows: what implementation must obey and what stage 6 compiles; alternatives, rationale, and risks explain, creating no obligation unless a binding element references them. *(tech-design-conventions §3.3)*
- **Design index** — the class's projection (`index.md` + `index.json`, generated at `docgate` v2): the live decision graph — status, lineage (direct and transitive successors), `Serves` inverse map, and the `stale-serves` / `stale-builds-on` flags. *(tech-design-conventions §3.2)*
- **Seam** — the place where two parts of a system meet such that either side can change without editing the other; the spot where an interface lives (the interface is the contract, the seam is its location). Load-bearing in stage-3's panel rule: a question that *opens or replaces* a seam warrants parallel alternatives; one that *extends* an existing seam does not. Avoid: *boundary* (overloaded), *interface* (the contract at the seam, not the place). *(Feathers; brainstorm:tech-design-brainstorm#T-1)*
- **Deletion test** — the shallow-module probe: imagine deleting the module — if complexity vanishes it was a pass-through; if it reappears across N callers it was earning its keep. Review vocabulary for §4 alternatives and deepening arguments. *(Ousterhout, via the 2026-07-09 design-discipline survey)*
- **One adapter = hypothetical seam; two = real** — don't introduce a port or interface unless at least two adapters are justified (typically production + test); a single-adapter seam is indirection wearing a contract. The guard behind the template's testing-strategy prompt and the panel's seam calls. *(tech-design-template §3.x menu)*

## The review protocol

- **Closable finding** — a review finding that names its own acceptance condition at birth; whether a revision closes it is checked against that stated condition, never against fresh taste. The anti-ping-pong unit. *(brainstorm:authoring-reviewers#T-1)*
- **Scope lock** — the convergence rule that a re-review may examine only the previously named defects plus regressions in changed spans; new findings on unchanged text are protocol violations. *(brainstorm:authoring-reviewers#T-2)*
- **Review-feedback ledger** — the append-only home of record for human review comments captured at the human-facing surfaces (doc-review, code host), each a closable comment→disposition→outcome entry cross-linked to the existing partial captures (`review-report/v1`'s M2 residual, the Argus `E-n` dispositions) so the factory's learning and traceability loops can read them; federated, never a replacement for those captures. · avoid: bare *feedback* (overloaded — `FeedbackRound` the react-loop, PR feedback threads, feedback events, `feedback-stalled`); *review record* (collides with `review-report/v1`). *(brainstorm:review-feedback-capture#T-1; prd:review-feedback-capture)*

## The AI Engineer (Argus)

- **AI Engineer** — the domain-model role: a separate agent holding the human engineer's delegated decision authority, interacting with pyxis as an automated counterparty; the stages keep their contracts and gain this counterparty. *(argus PRD §4.1; brainstorm:autonomous-developer#D-1)*
- **Argus** — the AI Engineer persona (the Argo's shipwright, the hundred-eyed watcher) — the thing a problem is handed to in prose and product language. The harness skill that instantiates it is **`/pyxis-argus`** (directory/`name:` `pyxis-argus`), not the bare persona word. Avoid: treating "Argus" and the slash-command as interchangeable after the skill-command-prefix rename; autonomous developer (informal description only). *(argus PRD header; brainstorm:autonomous-developer#D-9; brainstorm:skill-command-prefix#T-1; prd:skill-command-prefix FR-5)*
- **Decision principal** — the role stage contracts address: the human operator, or the AI Engineer under grant; every ruling records its principal identity and authority-contract version, never blended. *(argus PRD FR-12; brainstorm:autonomous-developer#D-6)*
- **Authority contract** — the agent's policy object: the versioned-data boundary of what it may rule versus must escalate; promoted only at checkpoints on evidence, demoted immediately on a missed-breaking, never self-amended. *(argus PRD FR-11/FR-14; brainstorm:autonomous-developer#D-3)*
- **Reasonable assumption** — the agent's default gap-filler: recorded, attributed, standing until overturned; legal iff it clears the tier check (no governance conflict), the channel check (standing content moves only by amendment/supersession), and the regression check (no unamended contract breaks). *(argus PRD FR-4/FR-5; brainstorm:autonomous-developer#D-4, #D-5)*
- **Breaking decision** — the escalation class: a governance override or a convergence deadlock — never assumed through; emitted as a decision brief, parking the problem fail-closed. *(argus PRD FR-6; brainstorm:autonomous-developer#D-5)*
- **Problem ledger** — the human's idea verbatim plus every accreted breaking-call answer (and any optional pre-rulings or envelope override): the root artifact agent rulings anchor to. *(argus PRD FR-1/FR-8; brainstorm:autonomous-developer#D-4, #D-6)*
- **Delivery ledger** — the per-problem driving state: stage position, open items, escalation states and ages — files-as-truth, resumable by a fresh session. *(argus PRD FR-2/FR-15; brainstorm:autonomous-developer#D-8)*

## docgate checks

- **History arm** — a docgate check that requires a git merge-base and compares merged content against the working tree to catch an edited or removed previously-merged entry; the append-only enforcer for the Argus ledger classes (DINV-1/2). Avoid: "immutability check" (overloaded with `check-immutable`, which governs a different, disjoint set). *(prd:argus-ledger-lint; brainstorm:argus-ledger-lint#T-1)*
- **Cross-document arm** — a base-free docgate check that scans the whole corpus for a citation resolving into a forbidden region — a `delivery:<slug>#` reference landing in the regenerable derived-state block rather than a journal `E-n` (DINV-6); recognizes a real citation by target-resolvability into an existing ledger, never by string shape. Avoid: "link check" (`doc-link-integrity` owns relative-link resolution; this is a citation-target-legality check). *(prd:argus-ledger-lint; brainstorm:argus-ledger-lint#T-2)*
- **Structure arm** — the third Argus ledger-lint arm: a base-free docgate check parsing the authority-contract file for its structural invariants (DINV-3 attribution present · DINV-4 tier-in-ladder + no bare pointer flip · DINV-5 no grant of a never-class act) — the mechanical form of the authority-contract template's Appendix checklist; complements the *history arm* and *cross-document arm*. Avoid: "immutability check" (`check-immutable`'s disjoint set), "ledger arm" (it targets the authority contract, not the `A-n`/`E-n` ledgers). *(prd:argus-boundary-enforcement; docs/tech-design/argus-authority-contract-structure-arm.md; brainstorm:argus-boundary-enforcement#T-1)*
- **Attribution gate** — a CI check that fails a PR whose **Argus-authored** diff touches a protected path (the authority contract, a governance doc, or a file outside the drive's declared scope); keys on authorship, so it never impedes a human-authored PR to the same paths. Its authorship *derivation* is hardened by the superseding design (produced signal + content binding + positive human establishment — see "Argus attribution hardening" below). Avoid: "author check" (too broad — scoped to Argus + protected paths), "governance gate" (`check-governing` owns governing-doc immutability regardless of author). *(prd:argus-boundary-enforcement; docs/tech-design/argus-attribution-gate.md → superseded by docs/tech-design/argus-attribution-hardening.md; brainstorm:argus-boundary-enforcement#T-2)*
- **Contract gate** — the mechanical stage-6 gate as a `docgate contract-gate <feature>` mode: a read-only pass that resolves a feature's assembled contract from the machine faces and composes five deterministic checks (currency · inverse-coverage · link · structural-completeness · compilability) into one closed feature-scoped verdict, materializing nothing on a clean pass and one git-committed dual-face defect report on a bounce; hard at planning entry, advisory on contract-doc PRs. The mechanical floor only — the LLM-judgment layer is deferred (#419), its verdict slot reserved-but-not-evaluated. Avoid: "contract compiler"/"translator" (reserved for the eventual LLM-inclusive capability — a passing gate materializes nothing, so the compiler framing is a misnomer), "contract check" (it is a composed mode over several checks, not one). *(prd:contract-gate; docs/tech-design/contract-gate-v1.md; brainstorm:contract-compiler-2#D-1)*

## Argus enforcement

- **Protected path** — a repo path a drive may not write: the authority contract, any frozen/merged document, another problem's ledger, or a path outside the current drive's declared scope. The write-hook layer denies a write to one at write time; the attribution gate refuses an Argus-authored diff touching one at CI. The two are the honest layer split: the write hook is the fast at-write-time layer (bypassable out-of-band), the structure arm and attribution gate are the unbypassable merge-boundary backstop. Avoid: "governed path" (overlaps the narrower governing-doc set). *(prd:argus-boundary-enforcement; docs/tech-design/argus-write-hook.md · docs/tech-design/argus-attribution-gate.md; brainstorm:argus-boundary-enforcement#T-3)*
- **Declared scope** — the set of paths a given drive is permitted to write (its own problem's ledgers, the documents it is authoring for that problem); a write outside it is a protected-path violation — the unit the write hooks and the attribution gate both test "in-scope-ness" against. The width is derived author-independently — from a problem's committed delivery ledger, or, on a brand-new problem's first PR, a slug-derived fixed set ∪ a fixed named allowlist — never from an author-writable same-PR signal. Avoid: "workspace" (implies a filesystem sandbox, one candidate mechanism, not the concept). *(prd:argus-boundary-enforcement; internal/argus/boundary; brainstorm:argus-boundary-enforcement#T-4)*

## The unattended drive

- **AUTO lane / HUMAN lane** — the two lanes of the risk-tiered merge-approval split: AUTO = a dedicated machine identity approves and merges a floor-clearing proposal once every required mechanical check is green (bot-attributed, bound to the exact head revision, goal-verified after); HUMAN = the default lane — a human approval + merge, exactly as today. Avoid: "auto-merge" as a bare noun (names the act, not the lane), "fast lane" (implies speed, not risk class). *(prd:argus-unattended-drive; quality-and-merge baseline GATE-4/GATE-5; brainstorm:argus-unattended-drive#T-1)*
- **Floor-clearing** — of a proposal: clearing the deterministic floor — zero hard-gate hits (control-plane paths, governance documents, the risk policy and activation state, the Argus authority contract and agent home), an operator-ratified AUTO-eligible change class covering the whole diff, and every required mechanical check green. The floor is versioned policy data derived from the diff's paths and classes, never author-declared; any hit routes HUMAN, non-negotiably. Avoid: "low-risk" as a synonym (the floor is computed, not felt). *(prd:argus-unattended-drive FR-2/FR-3; brainstorm:argus-unattended-drive#T-2)*
- **Wake signal** — the normalized, instruction-free notification (problem slug + touch reason, nothing else) that an awaited external completion has occurred, re-entering a drive at its front door; the resumed drive trusts only its own resume protocol — journal replay + goal-object verification — never the signal's content. A lost signal is caught by the bounded, stated-cost backstop. Avoid: "trigger with payload", "callback" (both imply carried logic — AP-2 forbids it). *(prd:argus-unattended-drive FR-14/FR-15/FR-17; brainstorm:argus-unattended-drive#T-3)*
- **Activation (AUTO lane)** — the operator's recorded enforcement flip: the org backstop change plus ratification of the initial AUTO-eligible class set; before it the lane runs shadow-only (classify + record, act on nothing), and the lane structurally refuses enforcement in its absence. Avoid: "rollout" (activation is one owned act, not a percentage). *(prd:argus-unattended-drive FR-8/FR-9; problem:argus-unattended-drive#A-1; brainstorm:argus-unattended-drive#T-4)*
- **Self-drive** — colloquial umbrella for the composed outcome: a feature integration drive kept moving unattended by the wake capability (the state reader, wake channel, and status verb of prd:self-drive-wake). Not a contract term — requirement text names the specific piece (*wake signal*, *wake channel*, *state reader*, *feature integration drive*). Avoid: "self-drive" in requirement/contract text. *(prd:self-drive-wake; brainstorm:self-drive-wake#T-1)*

## Argus attribution hardening

- **Produced authorship signal** — an Argus-authorship marker generated *by construction* at the point commits are authored (the supervisor/harness commit hook on the repo's own `core.hooksPath` surface, out of the drive's reach), never chosen by the model and never hand-added, so every commit a drive's work lands as carries it. Repairs the frozen gate's *latent* signal — a trailer nothing produced. Avoid: "trailer" (names one candidate mechanism — a commit-message line — not the concept; the produced signal may be a signature, an attestation, or a trailer), "Argus-Drive trailer" (the specific mechanism-of-record, not the concept). *(prd:argus-boundary-enforcement/FR-12; docs/tech-design/argus-attribution-hardening.md §3.1, #DINV-3; brainstorm:argus-attribution-hardening#T-1)*
- **Forgery-resistant in strength** — the property that a mis-behaving or injected drive *cannot* forge, replay, or omit-to-masquerade the authorship signal (the evade direction closed), as distinct from forgery-resistant in *direction* (repo-internal, credential-free, badge-independent — already held by the frozen derivation); reached credential-free by siting the producer out of the drive's reach plus an in-tree content binding the gate re-derives via `git` so a replayed trailer is detectable. Avoid: "forgery-resistant" unqualified (the frozen design uses it for the direction; this feature adds the strength), "unforgeable" (the raw-commit-access residual is the honestly-owned limit — cryptographic strength needs an operator-owned signing key, deliberately not introduced). *(prd:argus-boundary-enforcement/FR-12; docs/tech-design/argus-attribution-hardening.md §3.2, #DINV-4; brainstorm:argus-attribution-hardening#T-2)*
- **Positively-established authorship** — deriving a diff's author as *positively-Argus* or *positively-human* on the protected subset, rather than inferring "human" from the *absence* of an Argus signal; the three-state distinction (positively-Argus / positively-human / underivable) that lets absence fail closed without refusing a legitimate human PR, under a **positively-Argus-wins precedence** so a drive-plantable human attestation can never launder a positively-Argus diff (the both-signals collision refuses). Human authorship is established by a positive attestation trailer via its own single-sourced reader — no step beyond the ordinary protected-path PR. Avoid: "attribution" alone (too broad — this is the positive, three-state form the human-author guardrail needs). *(prd:argus-boundary-enforcement/FR-13; docs/tech-design/argus-attribution-hardening.md §3.3, #DINV-5; brainstorm:argus-attribution-hardening#T-3)*

## Access surfaces

- **Reading room** — the read-only corpus access surface (browse · search · trace · progress) chartered as the workbench-ui feature; composes the codified renderers and the review loop, holds no authority of its own. Avoid: portal, dashboard (names one panel, not the surface), viewer (taken by plan-viewer's page). *(brainstorm:workbench-ui#T-1)*

## The local executor (implement-now)

- **in-session run** — synchronous, same-session, same-hardware execution of a frozen plan's ready tasks by the invoking harness session under ambient/local policy, driven by the operator (attended) or argus (unattended); the `/implement-now` command. Contrasted with **fleet execution** — asynchronous pickup by hardware-separated, umbrella-policy-governed nodes. Avoid: *local* (the fleet pool is also local-machine-capable; the axis is synchronicity/same-hardware, not location). *(prd:implement-now; brainstorm:implement-now#T-1)*
- **umbrella policy** — fleet/org-level governance a node layer enforces over workers (managed-set/org policy, risk & size caps, resource limits, node leases/heartbeats) — the remote runtime's value-add, distinct from a task's own **charter** and from argus's **authority contract**. Avoid: bare *policy* (overloaded — charter, authority contract, and fleet governance are all "policy"). *(prd:implement-now; brainstorm:implement-now#T-2)*

## Execution-demand routing

- **Execution demand** — the vendor-neutral capability, deliberation, context, and assurance minimums frozen for a model-backed task and resolved by a runtime adapter into native launch settings. Avoid: bare *complexity* (it conflates cognitive difficulty, consequence, size, and runtime capacity). *(prd:planner-driven-model-routing; brainstorm:planner-driven-model-routing#T-1)*
- **Impact scope** — the breadth of consumers or system behavior that can be affected if a task's change is wrong (`contained | multi_surface | system_wide`). Avoid: *blast radius* (already the PRD-amendment impact tier). *(prd:planner-driven-model-routing; brainstorm:planner-driven-model-routing#T-2)*
- **Architectural role** — how central the changed surface is to the product architecture (`feature_local | shared_substrate | system_core`). Avoid: *Foundation* (already the task's dependency-graph position). *(prd:planner-driven-model-routing; brainstorm:planner-driven-model-routing#T-3)*
- **Assurance floor** — the minimum scrutiny required by consequence and closed risk-policy signals (`ordinary | elevated | critical`), mechanically derived and planner-raise-only; the proposal classifier may raise it from the actual diff. Avoid: bare *risk tier* (the merge lane owns proposal-risk classification). *(prd:planner-driven-model-routing; brainstorm:planner-driven-model-routing#T-4)*
- **Execution profile** — the frozen tuple of minimum semantic requirements (`capability`, `deliberation`, `context`, `assurance`) derived from a task assessment and resolved by one harness adapter into native launch settings. Avoid: *rung* (collapses independent requirements and conflicts with the verification-ladder term). *(prd:planner-driven-model-routing; brainstorm:planner-driven-model-routing#T-5)*
- **Harness adapter** — the Pyxis-owned runtime implementation for one external agentic CLI, including semantic-profile-to-native-model-and-effort resolution. Avoid: *harness owns routing* (the external CLI does not interpret Pyxis execution-demand fields). *(prd:planner-driven-model-routing; brainstorm:planner-driven-model-routing#T-6)*

## The feature implementation drive

- **Feature integration drive** — the durable lifecycle that routes one frozen feature DAG through owned execution, human-reviewed task integration on a feature branch, candidate-merge e2e, repair, and verified delivery to main. Avoid: *implement-now run* (one executor sweep, not the lifecycle), *feature workspace* (only its durable substrate). *(prd:feature-implementation-drive; brainstorm:feature-implementation-drive#T-1)*
- **Feature execution ownership** — the exclusive, durable assignment of all implementation and feedback-repair attempts for one feature to a local registered machine or remote execution domain until explicit handoff or release. Avoid: *task claim* (locks one current issue only), *process lock* (ownership survives process exit). *(prd:feature-implementation-drive; brainstorm:feature-implementation-drive#T-2)*
- **Candidate merge** — a disposable, non-mutating combination of an exact feature head with an exact target-main head, whose resulting identity is the subject of terminal e2e evidence. Avoid: *feature SHA* (omits the mainline input), *merge preview* (does not imply evidence binding). *(prd:feature-implementation-drive; brainstorm:feature-implementation-drive#T-3)*

## The verification harness (implementation-verification)

- **Verification manifest** — the closed-schema, versioned file on the pyxis-config surface (the sanctioned per-repo configuration surface, materialized under the system tree — design:installer-v1 §3.7) binding verification verbs to a repo's own commands (plus test globs, baseline location, per-verb env allowlist); governing policy data, human-authored — runtime executes it, never guesses. Avoid: bare *manifest* (GOV-1's primitive manifest), *repo memory* (VNEXT-6's descriptive model — this is governing, that is descriptive). *(prd:implementation-verification FR-5; brainstorm:implementation-verification#T-1)*
- **Ladder / rung** — the latency-ordered sequence of verification layers the implementing agent climbs (instant checks first, execution reality last); a rung is one layer with one verdict, and a run stops at the first failing rung. Avoid: *phases* (pipeline stages own it), *gates* (merge-lane and PRD sign-offs own it). *(prd:implementation-verification FR-1; brainstorm:implementation-verification#T-2)*
- **Falsification check** — the rung that reverts the non-test half of a diff and demands the new or changed tests fail; a test passing without its implementation is tautological and reds the run. Avoid: *mutation testing* (a different, deferred technique — systematic seeded mutants, not one revert). *(prd:implementation-verification FR-11; brainstorm:implementation-verification#T-3)*

## The proposal reviewer (impl-review)

- **Proposal boundary** — the stage-8 tail moment a factory proposal is reviewed: the verification ladder is green (codegate passed), the implementing worker's context is still warm, and the PR has not yet been raised. impl-review runs **once** here (never inside the fix loop, never as a cold post-raise check), and any post-review change to the proposal forces a re-review so the verdict stays bound to the tree it certifies. Avoid: *proposal = the PR* (implement-now pins that; the boundary is a pre-raise moment, before a PR exists — FND-28's collision), *PR-check* (the cold-after-raise form, correct only for the deferred remote twin). *(prd:impl-review FR-1; design:impl-review-v1 §3.4; brainstorm:impl-review#D-1)*
- **impl-review** — the third instance of the unmanned reviewer program (after prd-review and tech-design-review): LLM code review of each factory proposal at the proposal boundary through four blind fresh-context lenses (spec-fidelity · design-conformance · security-abuse · correctness-critic) over one shared context pack, emitting closable schema'd findings in the closed `impl-review-report/v1` payload persisted on the proposal, and a **downgrade-only** verdict (approve · approve-with-advisories · request-changes · escalate) that can force the HUMAN lane or bounce to the worker but never grants AUTO. Advisory until a ten-review adoption checkpoint. Avoid: *code review* unqualified (names the activity, not this bounded program instance), *the critic* (one of its four lenses, not the whole reviewer). *(prd:impl-review; design:impl-review-v1; brainstorm:impl-review#D-1)*

## The installer

- **release manifest** — the versioned, hash-carrying inventory a Pyxis release ships: every installed file with its ownership class; what converge reads, doctor diffs, and repair restores from. Avoid: bare *manifest* (GOV-1's primitive manifest and implementation-verification's verification manifest both claim it). *(prd:installer FR-1; brainstorm:installer#T-1)*
- **converge** — the idempotent reconcile of a repository against its pinned release manifest, acting per ownership class: repair engine-verbatim files byte-exact, validate-never-rewrite repo-owned ones, regenerate generated ones. Install, re-run/repair, and (later) upgrade are all the same converge. Avoid: *sync* (directionless), *scaffold* (SCAF-1's one-shot-creation sense), *copy*. *(prd:installer FR-5/FR-6; brainstorm:installer#T-2)*
- **ownership class** — the per-file marking in the release manifest — engine-verbatim · repo-owned · generated — deciding what converge may do to that file. Avoid: *mutability class* (AP-7's document classes). *(prd:installer FR-5; brainstorm:installer#T-3)*
- **payload** — the engine-owned artifact set a release ships beyond the binaries: the in-repo system tree of skills, templates, authoring guides, scripts, hooks, and vendored runtimes, enumerated by the release manifest. Avoid: *bundle* (the forbidden esbuild sense in the vendoring rules). *(prd:installer FR-1; brainstorm:installer#T-4)*
- **offline floor** — the guaranteed-working minimal binding of an installed repo: local git + the local work-item store + hook-run gates, zero network after the release-artifact fetch. Avoid: *air-gapped mode* (overstates — the artifact fetch happened). *(prd:installer FR-13; brainstorm:installer#T-5)*

## Config-driven portability

- **target-facing surface** — an engine-touched path, ref, or file that lives in the *adopter's* namespace (doc paths, the default branch/remote, root-level convention files like `AGENTS.md`, the CLI vendor pointers) and therefore must resolve from repo config; distinct from the engine's own system-tree paths, which live in Pyxis's own namespace and need no config. Avoid: bare *surface* (overloaded — access surfaces, CLI surfaces, routing surface). *(prd:config-driven-portability; brainstorm:config-driven-portability#T-1)*

## The channel inbox

- **channel bulletin** — a signed, append-only, closed-schema notice the distributor publishes on the release channel for operators to receive inside their agentic CLI; the message unit of the inbox. The new-version advisory is derived locally (pin-vs-latest), never authored. Avoid: *notification* (the delivery act, not the unit), *update channel* (a rollout cohort — `brainstorm:installer#O-7`, a different thing). *(prd:channel-inbox; brainstorm:channel-inbox#T-1)*
- **severity tier** — a bulletin's dedupe-governing class: `advisory` (shown once via the seen-ledger, muteable) versus `blocking` (re-fires every session until the condition clears, not muteable — the emergency lane). Avoid: *priority*, *level* (imply an ordinal scale, not the two-valued dedupe/mute contract). *(prd:channel-inbox; brainstorm:channel-inbox#T-2)*
- **seen-ledger** — the user-global record of which advisory bulletins an operator has already been shown, so each fires once per operator; lives beside the mute state and the channel snapshot in user-global (XDG) state, never in repo config. Avoid: *read receipt* (implies a report back to the sender — explicitly out of scope). *(prd:channel-inbox; brainstorm:channel-inbox#T-3)*

## The maintenance sweep

- **Maintenance sweep** — stage 11's bounded, read-only factory pass detecting operational rot as typed findings with named remedies; never fixes, never gates a proposal; on demand or host-scheduled (the wake-tick pattern). Avoid: *janitor* (implies mutation), *audit* (implies human judgment). *(prd:maintenance-sweep; brainstorm:maintenance-sweep#T-1)*
- **Rot finding** — one typed maintenance-sweep emission: detector, subject, evidence, named remedy; advisory by construction — consumers dispose it (fix, waive, or file). Avoid: *violation* (the sweep gates nothing). *(prd:maintenance-sweep FR-1; brainstorm:maintenance-sweep#T-2)*
- **Unwired package** — a first-party package no shipped binary reaches (dead-feature rot — the class of the lane/wake wiring gap), as distinct from a deliberately library-only package, which carries a visible waiver. Avoid: *dead code* (names the symbol-level class, deliberately parked). *(prd:maintenance-sweep FR-2/FR-5; brainstorm:maintenance-sweep#T-3)*

## Existing-repo onboarding

- **adopt / adoption** — bringing an *existing, non-empty* repository under factory management by negotiation: inspect the tree, propose a reviewable plan, apply on approval, reverse cleanly. The `adopt` verb, distinct from the empty-repo install (which scaffolds a greenfield tree). A specialization of the settled term **onboarding** (repo onboarding), naming specifically the existing-repo path. Avoid: *onboarding* used to mean only the existing-repo case (onboarding also covers the empty-repo install); *install* for the existing-repo path (install is the init-time act). *(prd:existing-repo-onboarding; brainstorm:existing-repo-onboarding#T-1)*
- **adoption plan** — the durable, reviewable artifact `adopt` writes before anything is applied: a per-path ledger of what the factory will add, what it will chain into, which collisions resolve how, what the human must do by hand, and the declared **never-touch set**. The record of what was agreed; the input a later apply, re-apply, and undo consult. Avoid: *converge report* (converge's ephemeral would-write / refused-by-name over its own managed set, not the adoption negotiation); bare *plan* (overloaded — the pipeline's stage-6 plan). *(prd:existing-repo-onboarding; brainstorm:existing-repo-onboarding#T-2)*
- **install epoch** — the adoption-commit baseline recorded in the repo config; the gates judge only content changed after it, grandfathering the pre-existing corpus wholesale (the generalized-grandfathering shape of `prd:installer#Q-4`). Avoid: *grandfather list* (the enumerated per-check exception surface — the epoch is a single marker; the lists remain available alongside it for targeted exceptions). *(prd:existing-repo-onboarding; brainstorm:existing-repo-onboarding#T-3)*
- **never-touch set** — the paths an **adoption plan** declares the factory will not read into, write, or configure (the adopter's source, their CI, their docs, their owned convention files); the subject of the round-trip byte-identity assertion. Avoid: *repo-owned* (an **ownership class** converge manages; the never-touch set is content the factory does *not* manage at all). *(prd:existing-repo-onboarding; brainstorm:existing-repo-onboarding#T-4)*

## Worker transcript metrics

- **harness run** — one worker executing one task in one role (implementation or review) on one harness; model, effort and configuration are constant within it. Avoid: *session* (a harness's own notion, which need not align with a task), *phase* (pipeline-measurement's authoring-stage bracket — a different span entirely). *(prd:worker-transcript-metrics; brainstorm:worker-transcript-metrics#T-1)*
- **process record** — the record describing one launched agent process, one per transcript, written when that process ends. Avoid: *turn record* (a turn is a level inside this record, not the record); take care with *sublaunch record* — the routed-execution design names the same span, but which plane owns the record is unresolved. *(prd:worker-transcript-metrics; brainstorm:worker-transcript-metrics#T-2)*
- **task rollup** — the stored record aggregating a task's process records into one total. Avoid: *phase run record* (pipeline-measurement's per-phase record — a different unit); take care with *attempt record*, per the caveat above. *(prd:worker-transcript-metrics; brainstorm:worker-transcript-metrics#T-3)*

## Document-system rules of thumb

- **Never renumber** — numbers (sections, requirement IDs) are permanent anchors; new content appends under fresh numbers; update and deletion happen by superseding the numbered content. *(operator ruling; practiced in the amendment model)*
- **Supersession** — the only way approved content changes: a new unit/document under a fresh ID citing what it replaces; the old ID never returns. *(AP-7 / prd-template Appendix A)*
- **Builds-on** — the dependency/lineage edge between designs; it never changes the target's liveness (that is `Supersedes`' job). *(tech-design-conventions §3.1)*
- **Relevant-when** — the one-line "when to open me" routing field every governed document carries. *(KNOW-2 convention; factory header)*
- **Judge once, freeze as data** — judgments happen at the richest-context site and are recorded for downstream verbatim reads — the amendment model applies this to document evolution. *(AP-21)*
- **Codify over prompt** — mechanical rules become code, never prompt discipline; the reason the fold is a tool and not an LLM behavior. *(AP-10)*
