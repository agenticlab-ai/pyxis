## Round 1

### FND-1 — `Serves: FR-9` had no binding element

- **Severity**: blocking (CAL-2)
- **Lens**: upstream-alignment
- **Evidence**: design:header `Serves … prd:review-feedback-capture/FR-9` (coded-writer-only) — vs — no `DINV`/`A-row` implemented it (Serves-substance: the lint proves the anchor *resolves*, this lens proves it's *true*)
- **Acceptance condition**: bind FR-9 with a `DINV`/`A-row`, or drop it from `Serves`
- **Disposition**: applied — added DINV-6 (the coded writer is the sole entry producer; no hand-authoring) and cited FR-9 · #DINV-6 in A-2

### FND-2 — AP-13 (verified artifact) silently omitted from Principles

- **Severity**: blocking (CAL-2)
- **Lens**: upstream-alignment
- **Evidence**: design:§Principles cites AP-1/3/5/6/10/17/21/23/27, RW-3 — vs — the byte-verified projection (§3.1) and the resolution/append-only checks are a clear AP-13 instance (principles-honesty: a relevant AP was silently omitted)
- **Acceptance condition**: cite AP-13 (and AP-19, also relevant — capture fires only on observed events)
- **Disposition**: applied — added AP-13 and AP-19 to Principles

### FND-3 — DINV-3 stated a negative, not property-testable

- **Severity**: advisory (CAL-3)
- **Lens**: contract-quality
- **Evidence**: design:§3.4 DINV-3 "inference is never the mechanism" — vs — the binding-element bar (a `DINV` must be property-testable; "no inference exists" proves a negative)
- **Acceptance condition**: reframe DINV-3 as a positive, testable invariant
- **Disposition**: applied — DINV-3 now reads "every disposition transition names the observed resolving event it was set from; a transition citing no event is invalid"

### FND-4 — the projection's regeneration trigger was unspecified

- **Severity**: advisory (CAL-4)
- **Lens**: feasibility-completeness
- **Evidence**: design:§3.1 "generated by `docgate fold` … byte-verified in CI" — vs — the missing-concerns sweep: *when* the fold regenerates (on write / on read / CI-only) was unstated, leaving projection freshness undefined
- **Acceptance condition**: specify the fold's regeneration trigger
- **Disposition**: applied — §3.1 now states the fold regenerates on each entry write, byte-verified by `verify-generated` in CI + a desk hook (the PRD-ledger freshness contract)
