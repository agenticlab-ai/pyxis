**Plan:** implementation-verification — plan 001 (implementation-verification/001 · `docs/plans/implementation-verification/001-plan.md`) · **Design:** docs/tech-design/codegate-v1.md

## Goal

Rung 2 adjudicates honestly on healthy and red-main repos alike: any failure reds a baseline-less repo, only new failures red a baseline-bound one, shrinkage is recorded, and the baseline is born from an operator-run subcommand — never from run mode.

## Current behavior

The test verb executes like any repo verb (T3) but its result is exit-code-only; no baseline semantics exist.

## Desired behavior

With no baseline bound, any test failure reds rung 2; with a baseline bound, failure identities parse via the stack's ecosystem parser and the rung evaluates no-new-failures — failing on any failure absent from the baseline, recording observed shrinkage in the verdict; unparseable output with a baseline bound is a rung error, never an exit-code fallback; `codegate capture-baseline` runs the test verb, writes the baseline file (failure identities + capture provenance) at the manifest-declared path, and exits — run mode never writes it.

## Scope

- The rung-2 check with both evaluation modes and shrink recording.
- Failure-identity parsing for the Go stack via the ecosystem table (further stacks ride T10's fixtures).
- The baseline file format with capture provenance, and UB-9's fail-closed path.
- The `capture-baseline` subcommand with the DINV-6 write discipline.

## Out of scope

- Baseline growth enforcement beyond FR-8's machinery flag — human-lane by convention until the remote phase.
- Detection-assisted capture — the basis's WR-6.

## Key interfaces

- `BaselineFile` (identities + provenance), `EvaluateRung2(result, baseline) → RungResult` with shrink record; `FailureIdentityParser` per stack.

## Acceptance criteria

- [ ] A clean fixture passes and one seeded failing test reds rung 2 with no baseline bound; the red-main fixture (K pre-existing failures) passes with zero new failures and reds when one new failure is seeded.
- [ ] A baseline-shrink run records the shrink in the verdict's rung-2 entry.
- [ ] Garbage test output with a baseline bound yields rung-2 error; the same output with no baseline follows the exit-code path.
- [ ] `capture-baseline` produces a baseline the red-main fixture binds; a write-audit test proves run mode performs zero writes to manifest or baseline.
