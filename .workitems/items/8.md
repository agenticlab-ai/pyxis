**Plan:** implementation-verification — plan 001 (implementation-verification/001 · `docs/plans/implementation-verification/001-plan.md`) · **Design:** docs/tech-design/codegate-v1.md

## Goal

Silencing a test costs a named finding: deletions, skip markers, and hollowed assertions in the proposal diff are flagged structurally, and renames pass clean.

## Current behavior

A diff deleting or skip-marking a failing test changes nothing the harness sees; silence is free.

## Desired behavior

Over the shared diff set (T4's substrate), deletions of test-glob paths, added skip/exclusion markers, and modified tests whose assertion-pattern count drops each produce a test-delta finding naming the affected test; git rename detection runs first so moves and renames never fire the floors; all patterns are per-stack ecosystem-table data.

## Scope

- The test-delta check registered on rung 3, all three trigger classes.
- The per-stack skip-marker and assertion-pattern tables for the Go stack.
- Rename-safety via the diff set's rename detection.

## Out of scope

- Detection depth beyond the three-class floor — the design's Q2, grown by data PR.
- Any test execution — this check is purely structural.

## Key interfaces

- `TestDelta(diffset, tables) → []Finding`; ecosystem table entries `SkipMarkers`, `AssertionPatterns` keyed by stack.

## Acceptance criteria

- [ ] Catch seed 2 reds in each of its three classes: a deleted failing test, an added skip marker, and an assertion-removal (hollowed test), each finding naming the test.
- [ ] The rename/move-refactor fixture passes without a test-delta finding.
- [ ] Pattern-table additions require zero changes to the check unit (data-only growth proven by a test adding a pattern).
