**Plan:** implementation-verification — plan 001 (implementation-verification/001 · `docs/plans/implementation-verification/001-plan.md`) · **Design:** docs/tech-design/codegate-v1.md

## Goal

codegate ships the way the repo-layout conventions demand and proves its portability constraint: pinned static artifacts, an owned pin section, and one advisory headless CI run whose verdict matches a local run rung for rung.

## Current behavior

codegate builds from source only; no release artifacts, no pin section, no evidence the identical harness runs headless in CI.

## Desired behavior

The release lane produces sha256-pinned static binaries per version; the operand acquisition config's closed schema gains the additive `codegate:` section (version + sha256) with the shim resolution path; an advisory (explicitly non-blocking) GitHub Actions job runs the identical harness headless on a commit and the comparison records rung-for-rung verdict parity with a local run (EVT-5); the living rollups gain the shipped capability's entries including the verdict-state and troubleshooting reference.

## Scope

- The goreleaser-style release configuration for codegate artifacts.
- The additive pin-section schema change with shim resolution.
- The advisory dry-run workflow + the parity comparison recording EVT-5.
- The living-doc entries (techspec/prd rollups; verdict-state reference).

## Out of scope

- Required-check registration or any enforcement semantics — the basis's WR-5, deliberately parked.
- Publishing cadence policy — releases cut when the operator tags.

## Key interfaces

- The `codegate:` pin-section schema; the dry-run workflow's parity comparison step; the release artifact naming convention.

## Acceptance criteria

- [ ] A release build produces static, sha256-pinned codegate artifacts resolvable through the shim against the new pin section.
- [ ] The pin section parses closed alongside the existing tool section; a wrong sha fails resolution fail-closed.
- [ ] The advisory workflow runs the identical harness headless and records rung-for-rung parity with a local verdict on the same commit (EVT-5), and is visibly non-blocking.
- [ ] The living rollups document the shipped capability: subcommands, verdict states, finding classes, and the troubleshooting reference.
