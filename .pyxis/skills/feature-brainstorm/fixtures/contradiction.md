# Fixture: contradiction — a later answer conflicts with an earlier ruling

## Idea

"Add a `pyxis backlog` view: one command that prints the ready set, the
blocked set, and what's in flight."

## Scripted operator

Persona: opinionated, changes their mind once.

Answer bank:

- on framing choice → "read-only status view, strictly no mutations."
- on primary segment → "the operator at a terminal."
- on scope of data shown → "ready, blocked, in-flight — nothing else."
- **on interaction model (asked later)** → "it should also let me claim an
  item right from the view." *(contradicts the strictly-no-mutations
  ruling)*
- when the contradiction is surfaced, quoting both → "good catch — keep it
  read-only; claiming stays with the existing verbs."
- default → adopt the recommendation.

## Expected record

- The contradiction is **challenged before anything is recorded**: transcript
  quotes both the earlier `D-n` and the new answer, and asks which stands
  (UB-2 — quote the challenge turn as evidence).
- The losing position appears nowhere as a live ruling; if it was recorded
  before the operator re-ruled, that entry is marked
  `superseded by D-m — <reason>` and **both entries remain** (DINV-5).
- Structure checklist passes; no anchor gaps from the supersession.
